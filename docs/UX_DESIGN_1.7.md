# DodoComm UX / 交互设计提案（待审核，暂未开工）

> 范围：S1–S8、A9–A17、B19、B23、C24–C27。
> 目标：在不破坏现有「首页 / 记录 / 设置」简洁感的前提下，把新能力收进清晰的层级里；所有设置使用同一套卡片、开关、底部弹层和状态色，避免功能堆成迷宫。

## 1. 设计原则

1. **三层结构**：底部 3 个主 Tab（首页 / 记录 / 设置）不变；复杂功能全部收进「设置 → 子页面」，主页面只放高频动作。
2. **先状态、后操作**：每个页面顶部先告诉用户「现在是否正常」，再给操作；失败态必须给出下一步，而不是只显示红字。
3. **一次只做一件事**：添加通道、路由规则、备份恢复都用全屏或大底部弹层，不塞进长滚动列表。
4. **默认安全**：应用锁、记录加密、通知内容隐藏、导出脱敏默认开启；高级/危险动作需二次确认。
5. **一致反馈**：点击→Snackbar；长任务→行内 loading + 进度；危险操作→确认弹层；成功后可撤销（删除记录、清空）。
6. **视觉延续 Klee 红粉金**：主色 `#D64550`、玫瑰 `#EF748B`、金 `#F2B544`、暖奶油底 `#FFF8F3`、深色暖棕黑 `#1A0F10`；新增「通道图标」使用同色系深浅底，不引入第二套品牌色。
7. **可达性**：点击区域 ≥ 48dp、对比度 ≥ 4.5:1、所有图标有 contentDescription、锁屏/密钥页禁截图。

**导航规则**
- 主 Tab 保留 3 个，不新增第 4 个 Tab；新增入口统一用 `SettingActionRow`（右侧 chevron）。
- 子页面：顶部返回箭头 + 页面标题；设置类页面底部不放主 Tab，回到设置时保留滚动位置。
- 表单未保存离开：弹「放弃修改？」；有自动保存的页面在标题下写「修改后立即生效」。
- 底部弹层用于：记录详情、选择通道类型、规则测试结果、确认危险操作；全屏用于：规则编辑、应用锁设置、备份向导、诊断报告。

## 3. 关键页面与交互

### 3.1 首页（S6、A16、C26）
- Hero 卡保留渐变、状态、开关；新增两个状态：**临时暂停中（显示 28:14 倒计时）**、**服务异常（提供「运行诊断」）**。
- 快捷动作改成 3 个等宽胶囊按钮：`暂停 30 分钟` / `测试推送` / `诊断`；暂停按钮点击后变成 `恢复转发`，倒计时结束自动恢复并 Snackbar 提示。
- 首页只显示最近 1 条记录（现在就是这样），更多去「记录」。
- 长按 Hero 卡进入「状态详情」底部弹层：通道连通性、最近一次错误、重试队列数、诊断入口。
- 桌面小组件 2×2：顶栏「DodoComm」+ 状态圆点 + 今日已送达数；点击=打开 App，长按=暂停/恢复（Android 小组件限制下用两个 hotspot 或第二行文字按钮）。

### 3.2 记录（S2、S3、S5）
- 标题栏右侧加搜索图标；点击展开搜索框（自动聚焦，输入即搜，300ms debounce），占位「搜索号码或内容」。
- 过滤 chips 一行：`全部` `已送达` `待重试` `已过滤`，右侧 `筛选` 打开底部弹层：
  - 发送者包含 / 内容关键词 / 日期范围（今天/近7天/自定义）/ 来源（SIM/通道）
  - 底部「重置」「应用」；应用后显示可关闭的筛选摘要 chip。
- 列表卡片：左侧头像；标题「发送者 · 状态 pill」；第二行内容摘要；右侧时间。识别到验证码时在摘要前加小标签 `验证码`。
- 点击记录 → 详情底部弹层（沿用现有），新增：
  - 验证码区域（大号数字 + 一键复制）
  - 推送通道 / 目标 / 尝试次数
  - 操作：重新发送、复制全文、导出单条、删除。
- 长按记录 → 多选模式（顶部出现计数与「全选」「导出」「删除」）；返回键退出多选。
- 列表空态/搜索空态沿用嘟嘟可插画；搜索无结果文案「没有找到匹配的短信」。

### 3.3 设置中心（整体）
- 用现有粘性分组标题 + 白色 SectionCard；每个分组 3–5 行，超出转「高级」子页。
- 推送通道入口显示「Bark · 已启用」等摘要；路由规则入口显示「3 条规则 · 默认 Bark」。
- 隐私组统一用盾牌 icon；危险行（清除全部数据）用 error 色，需输入「DELETE」确认。
- 「运行诊断」入口在后台组第一行，未通过项显示红色数量徽章。

### 3.4 应用锁（S1）
- 首次开启：
  1. 说明页（为什么锁、忘记 PIN 只能清除应用数据）→「设置 PIN」
  2. 6 位 PIN 输入 + 二次确认；可选「同时启用指纹/面容」
  3. 选择自动锁定时间：立即 / 1 分钟 / 5 分钟（默认 1 分钟）
- 解锁页：奶油底 + 嘟嘟可 + 4/6 位 PIN 点阵 + 数字键盘 + 指纹按钮；错误抖动，连续 5 次锁 30 秒；`FLAG_SECURE` 禁截图，最近任务缩略图隐藏。
- 生物识别失败可回落 PIN；没有生物识别则只显示 PIN。
- 设置里可「修改 PIN」「关闭应用锁」（需当前 PIN/生物识别）。
- 备份：开启应用锁时，配置备份必须设置独立密码（不能复用 PIN），避免锁死。

### 3.5 推送通道（A9、A10）
- 「推送通道」列表页：
  - 顶部说明「短信可以推送到多个通道；至少保留一个默认通道」
  - 卡片：图标 + 名称 + 状态（已启用 / 未配置 / 测试失败）+ 右侧开关；点击进入编辑页
  - 「添加通道」底部弹层：Bark / ntfy / Telegram / Pushover / Email；每项副标题说明成本/依赖
- Bark 编辑页：沿用现有服务器/Device Key/测试连接表单。
- ntfy：服务器地址（默认 https://ntfy.sh）、Topic、可选 Bearer Token、优先级。
- Telegram：Bot Token、Chat ID、解析模式；提供「如何获取」折叠说明。
- Pushover：User Key、App Token、优先级。
- Email：SMTP 主机/端口/加密方式/用户名/授权码/收件人；明确「授权码不是邮箱密码」。
- 每个编辑页底部固定「测试连接」按钮；测试结果行内显示成功/失败原因；未测试通过也可以保存但卡片显示黄点。
- 全局默认通道在列表顶部单选；路由规则可以覆盖默认。

### 3.6 路由规则（A10、A12）
- 列表：`默认目标` 卡片（默认通道 + 按 SIM 的覆盖）；下面「规则」按优先级从上到下：
  - 规则卡片：名称、条件摘要（如「SIM 2 且 内容含 验证码」）、目标通道、启用开关、拖拽手柄
  - 空态：「还没有规则，所有短信走默认通道」
- 添加/编辑规则（全屏）：
  1. 基本信息：名称
  2. 条件（全部满足）：SIM 槽位（任意/1/2）、发送者（包含/正则）、关键词（包含/正则）、时间段
  3. 动作：目标通道（可多选）、是否继续匹配下一条、失败时是否回退默认通道
  4. 「用示例测试」输入号码/内容，底部实时显示命中结果与最终目标
- 规则冲突：第一条命中即停止（开关可改「继续匹配」）；保存前提示目标通道是否启用。

### 3.7 模板与验证码（A11、S3）
- 推送样式页：
  - 标题模板（现有 chips + 新增 `{code}`、`{body}`）
  - 正文模板：默认 `{body}`；支持 `{sender}` `{sim}` `{time}` `{device}` `{number}` `{code}`
  - 验证码提取：开关「自动识别验证码」+ 规则说明；预览示例短信实时更新
  - `autoCopy` 改为三选一：关闭 / 复制全文 / 仅复制验证码
  - 「通知内容隐私」：常驻通知显示完整/仅数量/隐藏详情
- 验证码识别规则（可编辑高级正则）：默认 4–8 位数字，匹配「验证码|校验码|动态码|code」前后；结果在历史详情高亮，Bark 推送的 `copy` 字段可只放验证码（iOS 收到后复制）。

### 3.8 重试策略（A13）
- 设置→后台与可靠性→重试策略（子页）：
  - 最大尝试次数：1–10，默认 5
  - 退避：15s / 1min / 5min（指数或固定）
  - 仅 Wi-Fi 发送（默认关）；漫游时不发送（默认开）
  - 最大重试时长：1h / 6h / 24h
  - 文案明确「修改只影响之后的新失败；已入队任务使用原策略」
- 失败记录卡片上显示「下次重试约 xx:xx」。

### 3.9 运行诊断（A14、C26）
- 全屏诊断页：
  - 顶部总分：`12 项通过 / 1 项警告 / 0 项失败`，一键「重新检测」
  - 分组：权限、后台与电池、通知、网络、Bark 与其他通道、更新
  - 每项：icon + 标题 + 说明 + 状态（通过/警告/失败）+「去处理」按钮
  - 底部：复制脱敏报告 / 分享 / 查看本地崩溃日志（C26）
- 本地崩溃日志：默认只存本地，最多 10 条；查看页可复制、清空；不自动上传。

### 3.10 保活向导扩展（A15）
- 入口不变；首屏自动检测当前系统并显示「检测到 ColorOS / LineageOS / 其他」+「选择你的系统」。
- 支持：ColorOS、MIUI/HyperOS、One UI、原生/LineageOS、其他；每个 3–5 步，提供可跳转的系统设置 Intent；无法跳转时展示文字路径。
- 不做机型承诺，只写「适用于 XX 系统」；引导用户用诊断页验证结果。

### 3.11 注册自动化 / Tasker（A17）
- 设置→自动化与组件→自动化接口：
  - 列表展示支持的动作：测试推送、暂停、恢复、检查更新、查询状态
  - 每个动作提供 Broadcast action、extra 说明、adb 示例、Tasker 配置示例（折叠）
  - 安全：使用专用权限/签名校验；只开放非破坏性动作；文档说明风险
- 结果通过有序广播返回；无 Tasker 时页面只读，不影响主流程。

### 3.12 备份 / 导出 / 保留（S4、S5、S7）

**备份保护方式（已确认：两者都要）**
- 导出时生成随机数据密钥 DEK，备份内容用 AES-256-GCM 加密。
- DEK 同时用两条独立路径包装：
  1. **密码短语**：PBKDF2-HMAC-SHA256（高迭代）派生密钥包装 → 可跨设备恢复；
  2. **本机生物识别/设备凭据**：Android Keystore 生成不可导出的 AES 密钥，需 `BiometricPrompt`（或设备 PIN/图案）授权后包装 → 本机免输密码。
- 导入时先尝试本机生物识别；不可用/其他设备则输入密码短语。两种路径任一成功即可恢复，互为兜底。
- 忘记两条路径 = 备份不可恢复；不提供后门。应用锁 PIN 不复用于备份密码。

- 数据页：
  - 记录保留：7/30/90 天 / 永久 + 最多条数 500/1000/5000；显示当前占用；「立即清理」
  - 导出记录：CSV / JSON；范围（全部/今天/近7天/自定义）；「脱敏」默认开；导出成功后可分享
  - 备份与恢复：
    - 导出配置：选择「包含通道密钥」→ 设置备份密码（≥8 位，强度提示）→ 可选「同时绑定本机指纹/面容」→ SAF 保存 `.dodocomm-backup`
    - 导入：选择文件 → 优先弹本机生物识别；失败/其他设备则输入密码 → 预览（版本、通道数、规则数、是否覆盖）→「合并」或「替换」
    - 备份内容：设置、通道、路由、模板；不包含历史记录（记录单独导出）。
- 所有导出文件使用 UTF-8，CSV 带 BOM；文件名 `dodocomm-records-2026-10-30.csv`。

### 3.13 隐私 / 本地加密（B19）
- 本地 SQLite 的正文与发送者字段用 Android Keystore AES-GCM 加密；状态/时间/通道等元数据明文以支持排序和统计。
- 首次升级：自动迁移现有记录 → 显示一次性「正在加密本地记录」进度；失败则回滚并提示。
- 设置→隐私显示「本地记录：已加密（AES-256-GCM）」；「清除所有数据」需二次确认。
- 说明：加密密钥仅本机，卸载/清数据不可恢复；备份不包含历史正文。

### 3.14 远程管理（B23，默认关闭）
- 因没有可靠的入站通道，设计为**签名短信指令**：
  - 开启后在「远程管理」页生成随机密钥，显示为二维码/文本；用户把密钥保存到 iPhone。
  - 指令格式：`#DODO <action> <nonce> <hmac>`，支持 `PAUSE 30m`、`RESUME`、`STATUS`。
  - 仅接受启用时指定的可信号码；校验 HMAC-SHA256、nonce 时间窗（5 分钟）、防重放。
  - 执行结果通过默认 Bark 通道回推；失败不回复（避免短信轰炸）。
- 安全提示：短信可被伪造/转发，必须保留签名校验；不提供「清空数据/导出」等破坏性远程动作。
- 如觉得风险大，可砍掉此功能；建议放最后一阶段并默认关闭。

## 4. 视觉与组件增量

- **新增组件**：`SettingEntryCard`（带摘要/状态点）、`StatusPill`（已启用/未配置/失败）、`RuleCard`、`ChannelIcon`、`StepProgress`、`PinKeypad`、`DiagnosticRow`、`EmptyActionState`。
- **动效**：页面进入 200ms fade+slide（Compose 默认）；保存成功用 Snackbar；长按多选用 haptic；锁屏输错用 shake；下载/加密进度用 determinate bar。
- **颜色语义**：成功=现有 secondary 绿；警告=tertiary 金；失败=error 红；中性=outline。新增通道图标底色使用 primaryContainer/secondaryContainer/tertiaryContainer 三档。
- **暗色**：新卡片同现有 surfaceContainer；截图保护页使用纯色背景，避免暗色下发灰。
- **字体**：继续使用系统字体 + 现有 typography；验证码用 `displaySmall` + LetterSpacing。
